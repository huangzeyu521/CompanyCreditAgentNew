## 4. UI/UX 还原方案

### 4.1 全局原则
- 直接复用原型已经存在的 class 名（brand-600/text-muted 等），**不改名**；
- 复刻原型相同的 layout、padding、间距、字号；
- 所有图表保持原型同样的颜色、布局、提示行为；
- 所有交互（toast / modal / confirm / 切换 tab / 步骤切换）逻辑严格还原；
- 仅在原型未覆盖的细节（比如登录页）按截图风格重建；
- AI 助手抽屉是新增功能，但视觉沿用 brand 色和原型同款 lift/shadow-card 风格。

### 4.2 关键页面策略
- `login.html`：左侧 `grad-deep-blue` 渐变 + 装饰圆形 + 顶部 logo + 标题副标题 + 4 步功能列表（来自截图）+ 4 枚合规徽章；右白底卡片：账号密码 / SSO 切换 + 7天免登录 + 主按钮 → 跳工作台。
- `workbench.html`：与原型完全一致；KPI 4 卡 → 五步入口 → 待办 + 报告 + 预警 + 行业 + 隐私计算盒。
- `subject-rating.html`：5 步切换；在 step1/2/3/5 各设置一个"AI 智能助手"按钮，调起右侧抽屉，使用对应内置 Prompt 完成（见 §6）。
- `report-detail.html`：完整复刻 14 节报告；正文文案 100% 取自 copy-corpus.js（来源于 sfecr 文件夹）。

### 4.3 响应式
- 主断点 md=768、lg=1024。
- 1366×768 起所有功能可见；
- 1920×1080 内容居中 max-w-[1480px] 不拉伸；
- < 768 主侧栏折叠为汉堡按钮。

## 6. 大模型双增强专项设计

### 6.1 接口契约（DashScope 兼容）
- 端点：`https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation`（POST，SSE）
  或 OpenAI 兼容 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`
- 模型：`qwen3.6-max-preview`
- API key：在 `assets/js/config.js` 中 `window.AppConfig.apiKey`，由用户单独维护。
- 请求体：`{ model, messages:[{role,content}], stream:true, temperature:0.3 }`
- 流式：SSE `data: {choices:[{delta:{content:'…'}}]}` → 累积；`data: [DONE]`。

### 6.2 思考过程引擎（ThinkingEngine）
- 6 步标准化思考阶段（统一适配所有场景）：
  1. ✦ **解析任务** — 摘取用户意图与边界
  2. ✦ **匹配方法学/制度** — 检索远东评级方法学与公司制度
  3. ✦ **拉取公共信用** — 八大维度（GB/T 45255-2025）
  4. ✦ **跨域翻译/打分** — PD/LGD 映射
  5. ✦ **合规与红线核查** — D 级熔断 + 三级审核
  6. ✦ **生成结论与溯源**
- 实现：每接收到一段 SSE 内容，按特殊分隔标记（如 `[STEP-2]`）切换；同时按 token 节流模拟阶段进度（兜底，确保即使模型不输出标记也分阶段）。
- UI：左侧 6 个步骤（圆点 + 文字 + 进度环）；右侧主输出区按字逐字打字。

### 6.3 12 个内置专业 System Prompt（精选样例）
统一首部 `prompts.js` 提供：
```
你是远东资信评估有限公司部署的"企业信用状况综合评价智能体"——评级分析师的超级智能助手。
严格遵循：
  · 国办发〔2026〕8号《关于建立企业信用状况综合评价体系的实施方案》
  · GB/T 45255-2025《公共信用综合评价规范》（A/B/C/D 四级；八大维度）
  · 远东资信《信用评级业务程序指引》《信评委制度》《尽职调查制度》《跟踪评级制度》
  · 公共信用 D 级 → 行业评级不得评 A 级（含 AAA、AA+、AA、AA-、A+、A、A-）
原则：
  · 永远使用中文；专业、客观、不夸大；
  · 任何结论须可溯源（标注来源段、页码、字段）；
  · 不出现"承诺级别""保证收益"等违规话术；
  · 评级方法学、合规规则严禁自创；
  · 不替分析师做最终决策，仅提供建议。
输出必须按以下分阶段标记进行（流式）：
  [STEP-1]…[STEP-2]…[STEP-3]…[STEP-4]…[STEP-5]…[STEP-6]…
最后输出最终建议（含引用清单）。
```
12 场景在该首部基础上叠加任务专属指令（详见 prompts.js）。

### 6.4 失败 / 异常处理
- 401 / API key 缺失：弹层引导。
- 5xx / 超时：右下提示 + 重试按钮，自动 1 次重试。
- 网络中断：标识"已断开，请检查网络"。
- 内容触发本地 DLP（USCC 列表外发等）：阻断并 toast 提示。

## 7. 文案合规方案

### 7.1 抽取规则
- 来源：`materials/sfecr/`（业务制度、评级方法、信用研究、合规运行报告等）的 PDF。
- 抽取脚本：在第三步执行时用 `pdftotext` 抽取文本，按主题归档为 `data/sfecr-extracts/*.md`，每个 md 顶部记录原始 PDF 文件名。
- 文案库 `copy-corpus.js`：导出 `window.Copy = {...}` 的常量映射。每个常量 value 以 `{text, source}` 结构存在；模板渲染时取 `Copy.X.text`。
- 关键模板：评级报告 14 节标题、声明、跟踪评级 21 类、八大维度、评级等级 9 级释义、合规规则名等，全部基于 sfecr 提取。

### 7.2 校验机制
- 提供 `tools/copy-lint.js`（Node 简单脚本，使用 head 命令即可），扫描所有 .html / .js 中的中文短语，与 copy-corpus.js 比对；偏离即报警。
- 文档化要求：所有页面文案修改必须先更新 copy-corpus.js。

### 7.3 兜底策略
- sfecr 中不存在的、属于交互态的极少量文案（如"上一页"、"导出"），归类为 UI 通用按钮，在文案库 `Copy.UI.*` 单独命名空间，并标注 `source: UI 通用术语（非业务）`，与业务文案隔离。

## 8. 接口对接方案

### 8.1 后端接口（默认走 mock，可对接真实后端）
- 所有数据来自 `MockData`；预留 `services/api.js` 适配层，未来切真实接口直接换实现。
- 列表/详情/预警等读接口：异步函数返回 Promise，便于平滑替换。

### 8.2 大模型接口
- 单独 `ai-agent.js`（直接走浏览器 fetch + ReadableStream）；
- 安全：API key 直接放 `config.js` 仅用于本地 / 内网演示；生产应当走后端代理（已在 PDD §10.3 描述）。
